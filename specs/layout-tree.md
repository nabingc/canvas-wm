# Spec: layout-tree

## Goal

Provide the per-display **layout document** model and the two pure tree
passes everything else relies on:

- the immutable node model (split / panel / desktop) and the document that
  holds a tree plus floating and hidden panels;
- the split-id generator (`split-<random><counter>`), injectable for tests;
- `Normalize` — the bottom-up pass run after every structural edit that
  restores the tree invariants;
- `Sanitize` — the whole-document repair pass (unknown/duplicate windows,
  duplicate panels, duplicate desktops, bad weights), ending in `Normalize`.

No layout geometry (solver), no edits (dock/remove/dwindle), no JSON
serializer and no I/O are part of this feature.

## Placement

- Project: `src/CanvasWm.Core` (`net10.0`, BCL only; `System.Collections.Immutable`
  is part of the shared framework, so no package reference is added — B5 of
  `specs/solution-skeleton.md` still holds).
- Namespaces:
  - `CanvasWm.Core.Layout` — nodes, document, normaliser, sanitizer, id generator.
  - `CanvasWm.Core.Geometry` — two minimal value types (`Rect`, `Size`) needed

- Tests: `tests/CanvasWm.Core.Tests`, suggested files

### Nodes

```csharp
/// <summary>A node of a layout tree: exactly one of SplitNode, PanelNode, DesktopNode.</summary>
public abstract record LayoutNode
{
    private protected LayoutNode(string id);   // throws ArgumentNullException if id is null
    /// <summary>Node id; layout results are keyed by it, so it should be unique within a tree.</summary>
    public string Id { get; init; }
    /// <summary>True when this node is a DesktopNode with no child.</summary>
    public bool IsEmptyDesktop { get; }
}
```
The constructor is `private protected` so no node kinds other than the three
below can exist (closed hierarchy).

**Equality (all records above with collection members).** Each of
`SplitNode`, `PanelNode`, `HiddenDesktop`, `LayoutDocument` provides a
user-defined `Equals(T? other)` and `GetHashCode()` implementing **structural
value equality**: scalar members compared as usual, collection members
compared element-wise in order (`SequenceEqual`), nested nodes compared
recursively with their own `Equals`. `double` elements are compared with
`double.Equals` (so `NaN` equals `NaN`). Hash codes are consistent with
equality. Records without collection members (`DesktopNode`, `FloatingPanel`,
`HiddenPanel`, `Rect`, `Size`) use compiler-generated equality.

Collection properties are get-only (no `init`) so a `with` expression can
never produce a `default(ImmutableArray<T>)`; constructors copy their input
into a new `ImmutableArray<T>`.

## Behaviour

### Model

- **B1.** `Axis.X.ToRaw() == "x"`, `Axis.Y.ToRaw() == "y"`; `Cross` swaps them;
  `TryParseRaw` accepts exactly `"x"` and `"y"`.
- **B2.** `PanelNode.ForWindow(k)` = `PanelNode(id: k, views: [k], selected: k, tabbed: false)`.
- **B3.** `HasStrip = Tabbed && Views.Length > 1`;
  `IsNativeGroup = !Tabbed && Views.Length > 1`.
- **B4.** `new DesktopNode()` has `Id == "desktop"` and `Child == null`.
  `IsEmptyDesktop` is true exactly for a `DesktopNode` whose `Child` is null.
- **B5.** Constructors validate only nullness (see Public API). They accept
  raw shapes: empty child lists, empty view lists, weights lists of any
  length, any `double` weight (including 0, negatives, NaN, ±∞), duplicate
  ids, `Selected` not among `Views`. Repair is the job of `Normalize` and
  `Sanitize`.
- **B6.** Equality is structural as defined under *Equality*. Node instances
  are never mutated by any operation in this feature.

### Id generation

- **B7.** `UidGenerator` keeps a counter `c` (initially `initialCounter`).
  Each `Make` call atomically (lock or `Interlocked`) performs
  `c = (c + 1) % 1_000_000` and uses the new value; so from 0 the sequence is
  1, 2, …, 999999, 0, 1, ….
- **B8.** `Make(prefix)` returns `prefix + "-" + R + C` where
  `R = ToBase36(random())` truncated to its first 5 characters (shorter if the
  rendering is shorter) and `C = ToBase36(counter)`, with no separator between
  `R` and `C`. `random` is called exactly once per `Make`.
- **B9.** All split ids minted by later edit features use
  `Make(IdPrefixes.Split)`. Panel ids are window keys (B2); desktop ids
  default to `"desktop"`. Neither `Normalize` nor `Sanitize` mints ids.

### `Normalize(node)` (bottom-up, recursive)

- **B10. Panel.** `Views` empty → `null` (removed). Otherwise the same
  instance is returned (`Selected`/`Tabbed` are not checked).
- **B11. Desktop.** Never removed. `Child` null → same instance. Otherwise the
  child is normalised: if the result is the same instance as the child, the
  desktop instance is returned unchanged; if it is `null`, a desktop with the
  same id and `Child = null` is returned; otherwise a desktop with the same id
  and the normalised child.
- **B12. Split.** Let `out` be an empty list of (node, weight). For each
  original child index `i` in order:
  1. `n = Normalize(Children[i])`; if `n` is null, skip this child (its weight
     is discarded).
  2. `w = i < Weights.Length ? Weights[i] : 1.0` (`MissingWeight`).
  3. If `!(w > 0 && double.IsFinite(w))` then `w = 0.001` (`BadWeightReplacement`).
  4. If `n` is a `SplitNode` with the **same axis** as this split: let
     `S = Σ n.Weights`; append each `(n.Children[j], w × n.Weights[j] / S)` in
     order. (One level suffices because `n` is already normalised.)
  5. Otherwise append `(n, w)`.
  6. After all children:
     - `out` empty → return `null`;
     - exactly one entry → return that entry's node (the split is replaced by
       its child; the entry's weight is dropped);
     - two or more → let `T = Σ weights`; if `T` is not finite, first divide
       every weight by the largest weight (A6) and recompute `T`; then divide
       every weight by `T`.
- **B13. No-change shortcut.** With ≥ 2 entries, the **original instance** is
  returned if all hold: `out.Count == Children.Length`;
  `Weights.Length == Children.Length` (A3); for every `k`,
  `out[k].node.Equals(Children[k])` (structural); and
  `|out[k].weight − Weights[k]| <= 1e-12` (`NoChangeTolerance`; a NaN
  original weight therefore always counts as changed). Otherwise a new
  `SplitNode` with the **same `Id` and `Axis`**, the `out` nodes and the `out`
  weights is returned.
- **B14. Invariants after `Normalize` (non-null result `r`).** Every
  `SplitNode` in `r`: has ≥ 2 children; `Weights.Length == Children.Length`;
  every weight is > 0 and finite; weights sum to 1 within `1e-9`; no child is a
  `SplitNode` of the same axis. No `PanelNode` in `r` has empty `Views`. Every
  `DesktopNode` from the input is still present.
- **B15. Id stability.** `Normalize` never renames: every id in the result
  occurred in the input on a node of the same kind; a surviving split keeps
  its id and axis. Ids disappear only with removed nodes (emptied panel,
  emptied split, single-child split replaced by its child, same-axis child
  split merged into its parent — the parent's id stays).
- **B16. Non-goals of `Normalize`.** It does not enforce minimum sizes,
  de-duplicate windows or ids, fix `Selected`, require a desktop node, or
  touch anything outside the given node.
- **B17. Idempotence.** For any node `x` with `r = Normalize(x)` non-null,
  `Normalize(r)` returns `r` itself (same instance).

### `Sanitize(document, isKnown)`

- **B18. Shared state and order.** One set of seen panel ids and one set of
  seen window keys are shared across the whole call. Order of processing:
  (1) the tree root, depth-first, children in order; (2) `Floating` in list
  order; (3) `Hidden` in list order. Earlier occurrences win.
- **B19. Panel repair (`fixPanel`).** If the panel's `Id` is already in the
  seen panel-id set → the panel is dropped. Otherwise add `Id` to the set;
  keep, in order, each view `v` with `v` not in the seen-key set **and**
  `isKnown(v)` true, adding each kept `v` to the seen-key set (so a key
  duplicated inside one panel survives once). No survivors → panel dropped.
  Otherwise the result has the same `Id` and `Tabbed`, `Views` = survivors,
  and `Selected` = the original `Selected` if it is among the survivors,
  else the first survivor (this includes `Selected == null`).
- **B20. Desktop repair.** A flag "desktop kept" starts false. On meeting a
  `DesktopNode`:
  - if the flag is false: set it to true **before** repairing the child
    (A7); repair the child (null child stays null); if the repaired child is a
    `DesktopNode` it is discarded (child becomes null); return a desktop with
    the same id and the repaired child.
  - if the flag is true: return the repaired child (or null if it has none or
    it repairs to null) in place of this desktop.
  So the sanitized tree contains at most one `DesktopNode`, the first in
  pre-order.
- **B21. Split repair.** Repair each child in order, dropping those that
  repair to null. For each surviving child with original index `i`, its weight
  is `Weights[i]` if `i < Weights.Length`, else 1.0; a non-positive or
  non-finite value becomes **1.0** (`RepairWeight`, deliberately different
  from Normalize's 0.001 — A4). No surviving children → null. Otherwise build
  `SplitNode(sameId, sameAxis, weights, survivors)` and return
  `Normalize` of it.
- **B22. Root.** The repaired root (or null) is passed through `Normalize`
  once more (null stays null) and becomes the result's `Root`.
- **B23. Floating / hidden lists.** For each `FloatingPanel`, its `Panel` is
  repaired by B19; dropped → the entry is removed; otherwise the entry is kept
  with only `Panel` replaced (`Rect`, `Z`, `Size` unchanged, order kept). Same
  for `HiddenPanel` (`Restore` unchanged).
- **B24. Hidden desktop** is copied to the result unchanged (A8).
- **B25.** `Sanitize` calls `isKnown` only with view keys of panels it
  inspects; it never throws for any structurally valid (non-null) document.

## Edge cases & errors

- **E1.** Null arguments to constructors, `Normalize`, `Sanitize`, `Make`,
  `UidGenerator(...)` → `ArgumentNullException`. `initialCounter` outside
  `[0, 999999]` → `ArgumentOutOfRangeException`.
- **E2.** Weights list shorter than children: missing entries are 1.0 in both
  passes; never an index error. Longer than children: extra weights ignored;
  the result has exactly one weight per child.
- **E3.** A split whose children are all empty panels normalises to null; as
  a document root this yields `Root == null` (a document with no tree).
- **E4.** A split with a single child normalises to that child's normalised
  form, regardless of the child's weight value (even NaN).
- **E5.** Weights whose individual values are finite but whose sum overflows
  to +∞ are handled by the max-scaling step in B12.6 (no NaN/0 weights result).
- **E6.** Duplicate split or desktop ids are not detected by either pass
  (only duplicate panel ids are, in `Sanitize`). See A10.
- **E7.** `Normalize` may return a tree whose panels have `Selected` not in
  `Views`; only `Sanitize` fixes `Selected`.
- **E8.** A `DesktopNode` whose child is a `DesktopNode` is left as-is by
  `Normalize`; `Sanitize` flattens it per B20.

## Acceptance criteria

Notation as in the findings: `X[...]`/`Y[...]` = split on that axis, letters =
`PanelNode.ForWindow(letter)`, weights in parentheses, `∅` = panel with id
`"e"`/`"e2"`… and no views. Weight comparisons use absolute tolerance `1e-9`
unless stated. All criteria are xUnit tests in `tests/CanvasWm.Core.Tests`
with no OS access.

### Model
- **AC1** [mac] `Axis.X.ToRaw()=="x"`, `Axis.Y.ToRaw()=="y"`,
  `Axis.X.Cross()==Axis.Y`, `Axis.Y.Cross()==Axis.X`; `TryParseRaw("x")`/`("y")`
  succeed with the right value; `TryParseRaw("X")`, `("z")`, `("")`, `(null)`
  return false. (B1)
- **AC2** [mac] `PanelNode.ForWindow("w1")` has `Id=="w1"`, `Views==["w1"]`,
  `Selected=="w1"`, `Tabbed==false`, `HasStrip==false`,
  `IsNativeGroup==false`. (B2, B3)
- **AC3** [mac] Truth table: views `[a,b]` tabbed → `HasStrip` true,
  `IsNativeGroup` false; `[a,b]` not tabbed → false/true; `[a]` tabbed →
  false/false; `[]` either → false/false. (B3)
- **AC4** [mac] `new DesktopNode()` has `Id=="desktop"`, `Child==null`,
  `IsEmptyDesktop==true`; `new DesktopNode(a).IsEmptyDesktop==false`;
  `a.IsEmptyDesktop==false`. (B4)
- **AC5** [mac] Two independently constructed `X[a(0.5), Y[b(1), c(NaN)](0.5)]`
  trees are `Equals` and have equal hash codes; changing any one weight, axis,
  id, view, `Selected` or `Tabbed` makes them unequal. Two `LayoutDocument`s
  built from equal content are equal; two `HiddenDesktop`s with equal lists
  are equal. (B6)
- **AC6** [mac] Constructors throw `ArgumentNullException` for a null id, null
  collection, or null element; they accept empty lists, short weights,
  NaN/negative weights without throwing. `LayoutDocument(null)` has empty
  `Floating`/`Hidden` and `HiddenDesktop==null`; `LayoutDocument.Empty.Root`
  is null. (B5, E1)

### Normalize (findings worked examples 1–11)
- **AC7** [mac] `X[a(0.5), X[b(0.5), c(0.5)](0.5)]` (outer id `"o"`, inner
  `"i"`) → `X[a(0.5), b(0.25), c(0.25)]` with `Id=="o"`; no node in the result
  has id `"i"`. (Ex. 1, B12.4, B15)
- **AC8** [mac] `X[a(0.3), X[b(1), c(3)](0.7)]` → `X[a(0.3), b(0.175), c(0.525)]`. (Ex. 2)
- **AC9** [mac] `X[a(0.5), Y[b(1)](0.5)]` → `X[a(0.5), b(0.5)]`. (Ex. 3, B12.6)
- **AC10** [mac] `X[Y[∅(0.5), X[b(1), c(1)](0.5)](0.5), a(0.5)]` →
  `X[b(0.25), c(0.25), a(0.5)]`, order exactly b, c, a; outer id kept. (Ex. 4)
- **AC11** [mac] `Y[a(2), b(0)]` → `Y[a(2/2.001), b(0.001/2.001)]`, i.e.
  ≈ `[0.9995002499, 0.0004997501]` within `1e-9`. (Ex. 5, B12.3)
- **AC12** [mac] `X[a, b, c]` with `Weights=[1]` → weights `[1/3, 1/3, 1/3]`,
  `Weights.Length==3`; no exception. (Ex. 6, E2)
- **AC13** [mac] `X[a(-1), b(NaN)]` → `[0.5, 0.5]`; `X[a(+∞), b(1)]` →
  `[0.001/1.001, 1/1.001]`. (Ex. 7, B12.3)
- **AC14** [mac] `X[∅, ∅]` → `Normalize` returns null; `Sanitize` of a
  document whose root is `X[∅, ∅]` returns `Root == null`. (Ex. 8, E3)
- **AC15** [mac] `Desktop{child: X[∅]}` → a `DesktopNode` with the same id and
  `Child == null`. (Ex. 9, B11)
- **AC16** [mac] For `n = X[a(0.5), b(0.5)]`, `ReferenceEquals(Normalize(n), n)`;
  for `X[a(0.5), b(0.5 + 1e-13)]` also the same instance; for
  `X[a(0.5), b(0.6)]` a new instance with the same `Id` and weights
  `[0.5/1.1, 0.6/1.1]`. (Ex. 10, B13)
- **AC17** [mac] `Y[a(0.4), Desktop{}(0.6)]` → same instance returned. A lone
  `new DesktopNode()` → same instance. `PanelNode.ForWindow("a")` → same
  instance; a panel with empty `Views` → null; a panel whose `Selected` is not
  in `Views` → same instance. (Ex. 11, B10, B11, E7)
- **AC18** [mac] `X[a, b]` with `Weights=[0.5, 0.5, 0.7]` (extra weight) → new
  instance, `Weights==[0.5, 0.5]`. `X[a, b]` with `Weights=[0.5]` → new
  instance, weights `[1/3, 2/3]`. (A3, E2)
- **AC19** [mac] `X[a(1e308), b(1e308)]` → `[0.5, 0.5]`, all finite. (E5, A6)
- **AC20** [mac] `X[a(0.5), Y[b(NaN)](0.5)]` → `X[a(0.5), b(0.5)]` (single
  child replaces split; its own weight ignored). (E4)
- **AC21** [mac] Property test over ≥ 500 trees generated by a seeded
  `System.Random` (fixed seed, depth ≤ 5, fan-out 0–4, random axis, weights
  drawn from {random positive, 0, −1, NaN, +∞, missing}, ~20% empty panels,
  occasional empty desktops): for each non-null result, the B14 invariants
  hold, the B15 id property holds, and `Normalize(result)` returns the same
  instance (B17). Input trees are unchanged (still `Equals` a deep copy taken
  before the call).

### Sanitize (findings worked examples 12–14)
- **AC22** [mac] With `isKnown = k => k != "b"`, root
  `X[P1{id:"p1", views:[b,c], selected:b}(0.5), P2{id:"p2", views:[c,d], selected:c}(0.5)]`
  → `X[P1{views:[c], selected:c}, P2{views:[d], selected:d}]`, ids kept. (Ex. 12, B19)

## Assumptions

- **A1. Serializer deferred.** Chosen default: no JSON code in this feature
  (no `System.Text.Json` attributes or converters on the model). The store
  feature implements serialization against the following **wire-shape
  contract**, which this spec fixes so the model can satisfy it:
  - Node = flat JSON object with discriminator `"kind"` ∈ `"split"`,
    `"panel"`, `"desktop"`, plus that kind's fields at the same level, using
    the keys `id`, `axis` (`"x"`/`"y"` via `ToRaw`/`TryParseRaw`), `weights`,
    `children` (split); `id`, `views`, `selected`, `tabbed` (panel); `id`,
    `child` (desktop).
  - Document keys: `root`, `floating`, `hidden`, `hiddenDesktop`.
  Why: the model needs immutable arrays and private-protected constructors,
  which need custom converters; that work plus the per-display wrapper
  (`doc`, framings, owners, …) belongs with the store. *Review*: confirm.
- **A2. Missing-key defaults on decode (for the store feature).** Recommended
  defaults: `selected` → null, `tabbed` → false, `child` → null, `weights` →
  empty, `children` → empty, `views` → empty, `root` → null, `floating`/`hidden`
  → empty, `hiddenDesktop` → null, desktop `id` → `"desktop"`. Missing split
  or panel `id`, or unknown `kind`/`axis` → the store decides (suggest: reject
  the document). The model accepts all these shapes (B5) and `Sanitize`
  repairs them. Not observed in the studied app. *Needs human review.*
- **A3. Weights/children length mismatch.** Missing weights are 1.0 in both
  passes, and a split with `Weights.Length != Children.Length` is never
  considered unchanged by the no-change shortcut (the studied app would
  crash on this path). Why: the intended rule is clear and CanvasWM must not
  crash.
- **A4. Two bad-weight replacements kept as observed.** `Normalize` replaces a
  non-positive/non-finite weight with **0.001**; `Sanitize`'s split repair
  uses **1.0** (missing weights are 1.0 in both). Because `Sanitize` repairs
  weights before calling `Normalize`, sanitized trees never see the 0.001
  path. *Needs human review*: the inconsistency is faithful to the study, not
  a design choice; unifying on 1.0 would be a deliberate deviation.
- **A5. Equality of `double` weights** uses `double.Equals` (NaN equals NaN,
  0.0 equals −0.0). Only the no-change shortcut's weight test uses the 1e-12
  tolerance (where NaN never matches).
- **A6. Sum overflow guard** (B12.6 max-scaling) is a CanvasWM addition for an
  input the study never exercised; it changes no observed result (when the sum
  is finite, the step is skipped).
- **A7. First-desktop flag set before repairing its child.** The findings mark
  "a repaired child that is itself a desktop is discarded" as Inferred. With
  the flag set first that guard is purely defensive and `Desktop{Desktop{a}}`
  becomes `Desktop{a}` (no window lost). Setting the flag after the child
  would instead lose `a`. *Needs human review.*
- **A8. Hidden desktop untouched by Sanitize.** Findings rule 17 only lists
  root → floating → hidden; how `hiddenDesktop.floats` are repaired was not
  traced. Default: copied unchanged, so stale window keys there survive
  `Sanitize`. The hide/desktop feature may extend `Sanitize`; that will be a
  change to this spec and must be reported. *Needs human review.*
- **A9. Minimal `Rect`/`Size` introduced here.** `FloatingPanel` needs them
  and no geometry spec exists yet. Defined as plain positional record structs
  in `CanvasWm.Core.Geometry`; later features add members, not change shape.
- **A10. Id uniqueness not enforced.** Split/desktop ids are assumed unique
  (findings rule 7 is Inferred). Neither pass de-duplicates them; with the
  generator's random+counter scheme collisions are not expected. A later
  feature may add a check.
- **A11. `RestoreTarget` is an empty abstract record** placeholder whose
  concrete kinds belong to the hide/restore feature; this feature only
  carries it. `HiddenPanel.Restore` is non-null (as observed),
  `HiddenDesktop.Restore` nullable.
- **A12. Id generator.** Process-wide `UidGenerator.Shared` mirrors the study's
  global counter; edit features should take `IIdGenerator` as a parameter so
  tests inject a deterministic instance. Lowercase base 36, 5-char random
  prefix and modulus 1,000,000 kept as observed.
- **A13. Panel ids after tab edits** (merging tabs, splitting off a tab,
  regrouping) are out of scope; the tab feature must decide whether a merged
  panel keeps the anchor's id. Note for later: `Sanitize` drops a panel whose
  id repeats, so tab edits must not leave two panels sharing an id.
- **A14. When `Sanitize` runs and what `isKnown` checks** (load, display
  change, …) is decided by the Engine/store features; this spec only defines
  the pure function.
- **A15. Window key** is an opaque non-null string here; its format belongs to
  the window-system feature.
